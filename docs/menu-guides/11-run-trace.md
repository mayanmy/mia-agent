# 运行链路菜单新手引导

## 一、这个页面做什么

“运行链路”是空间 Owner/Manager 排查 Agent/Workflow 完整执行过程的页面，底层数据对象仍称 Run Trace。页面显示来源、状态、阶段耗时、输入输出预览和每一步详情。

## 二、页面按钮和筛选项

| 控件       | 作用                                             |
| ---------- | ------------------------------------------------ |
| 刷新       | 获取最新运行记录                                 |
| Request ID | 精确定位一次请求                                 |
| Agent ID   | 筛选某个 Agent                                   |
| 状态       | 筛选运行成功、失败、取消等状态                   |
| 来源       | 区分工作台、Widget、Service API、Workflow 等入口 |
| 查询       | 应用筛选                                         |
| 重置       | 清空条件                                         |
| 详情       | 打开运行输入、输出、错误和 Step 时间线           |

## 三、排查步骤

1. 在对话或 API 复现故障并复制 Request ID。
2. 进入“运行记录 → 运行链路”，填 Request ID，点击“查询”；从聊天消息点击“运行详情”时会在原页面直接打开对应抽屉。
3. 点击该行“详情”。
4. 先看总状态、耗时、输入和输出预览。
5. 再逐步展开 Step，定位第一个失败或耗时异常的阶段。

### 典型链路

```text
加载 Agent → 知识检索 → 模型调用 → 工具调用（可选）→ 最终回答 → 日志记录
```

### 效果预期

可以明确问题发生在检索、模型、工具、Workflow 节点还是客户端取消，而不是只看到“回答失败”。

## 四、常见判断

- **retrieval 很快但无 chunks**：查知识库索引、绑定和检索阈值。
- **LLM 首 token 很慢**：查上游队列、并发槽位、网络和首 token 超时。
- **tool failed**：点击“查看请求日志”，按同一 Request ID 查看工具详情。
- **canceled**：用户点停止、页面关闭或代理断开，通常不是模型错误。
- **Workflow 某节点 skipped**：检查条件分支或上游失败策略。

## 五、常见问题

- **普通成员看不到菜单**：运行记录由空间 Owner/Manager 使用，Member 不开放全空间列表。
- **输入输出被截断**：页面展示预览是为了控制日志大小，不代表运行时内容一定丢失。
- **没有记录**：确认请求确实到达当前环境，并检查 Request ID 和来源筛选。

⚠️ Trace 可能包含业务输入和模型输出。只授权管理员访问，并避免在排错截图中传播敏感内容。
