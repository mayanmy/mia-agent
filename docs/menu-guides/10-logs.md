# 请求日志菜单新手引导

## 一、这个页面做什么

当前“请求日志”页面重点展示工具选择与执行日志，用于回答：模型看到了哪些工具、请求了哪个工具、参数是什么、执行成功还是失败。

## 二、页面按钮和筛选项

| 控件 | 作用 |
| --- | --- |
| Request ID | 精确查一条请求链路 |
| Agent ID | 只看某个 Agent |
| 工具 ID | 只看某个工具 |
| 状态 | 可用工具、已请求、完成、失败、跳过 |
| 查询 | 按当前条件检索 |
| 重置 | 清空筛选条件 |
| 详情 | 打开工具调用详细记录 |

## 三、排查一次工具失败

### 操作步骤

1. 在“对话”复现问题，记录界面或响应中的 Request ID。
2. 进入“请求日志”；也可以在运行链路详情中点击“查看请求日志”，自动携带 Request ID。
3. 在 Request ID 输入框粘贴 ID，点击“查询”。
4. 按时间顺序观察 available → requested → completed/failed/skipped。
5. 点击“详情”，检查工具 ID、调用来源、参数、结果和错误信息。

### 示例

```text
Request ID：从失败对话复制
状态：失败
工具 ID：query_leave_balance
```

### 效果预期

能区分：模型没有选择工具、已经请求但校验失败、HTTP 执行失败、或执行成功但模型总结错误。

## 四、状态含义

- **可用工具**：本轮向模型暴露了该工具。
- **已请求**：模型或推断逻辑决定调用。
- **完成**：工具执行成功。
- **失败**：参数校验、网络、鉴权或远端返回失败。
- **跳过**：策略、审批、前置错误或条件导致未执行。

## 五、常见问题

- **完全没有日志**：Agent 未绑定工具，问题没有进入工具编排，或 Request ID 错误。
- **available 但没有 requested**：模型没选择；改善工具描述或明确要求调用。
- **requested 后 failed**：看详情中的参数、HTTP 状态和错误。
- **敏感字段看不到**：这是脱敏设计，不应尝试从普通日志恢复密钥。
- **请求日志与运行链路区别**：请求日志聚焦工具事件；运行链路展示整个 Agent/Workflow 执行阶段。

💡 先用 Request ID 精确定位，再用 Agent ID/工具 ID 做趋势排查，避免在大量日志里猜。
