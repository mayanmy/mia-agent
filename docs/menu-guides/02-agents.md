# Agent 菜单新手引导

## 一、这个页面做什么

Agent 是模型、System Prompt、知识库、工具、Workflow 和会话策略的组合。创建前至少要有一个启用的 Chat 模型。

## 二、页面按钮

| 按钮 | 作用 |
| --- | --- |
| 刷新 | 重新加载 Agent、模型和绑定摘要 |
| 新增 Agent | 打开创建弹窗 |
| 测试对话 | 进入内部 Chat 并选中该 Agent |
| 更多操作 → 发布 | 生成公开 Token，使分享/API/Widget 可用 |
| 复制链接 | 复制公开分享页地址 |
| 嵌入代码 | 生成单 Agent、多 Agent、SPA 或行内 Widget 代码 |
| 服务端 API Key | 创建、轮换、撤销后端调用 Key |
| 公开访问设置 | 设置到期时间、Origin 白名单和密码 |
| 取消发布 | 立即关闭公开入口 |
| 编辑 | 修改配置和绑定 |
| 删除 | 删除 Agent，操作前确认不再使用 |

## 三、创建 Agent

### 操作步骤

1. 点击“新增 Agent”。
2. 在“基础配置”填写名称、模型、描述和 System Prompt。
3. 设置 temperature、max_tokens、max_context_turns 和会话模式。
4. 分别进入“知识库绑定”“工具绑定”“Workflow 绑定”勾选能力。
5. 点击“创建”。

### 可复制示例

```text
名称：公司制度助手
描述：回答公司休假、报销和入职制度问题
temperature：0.2
max_tokens：1200
max_context_turns：6
会话模式：窗口可保留数据
启用：开
```

```text
你是公司制度助手。优先依据知识库回答；资料不足时回答“现有资料无法确认，请联系制度负责人”，不得编造。先给结论，再给办理步骤，最后列出参考资料。
```

### 效果预期

列表出现 Agent，模型名、工具数量、知识库数量和启用状态正确。

## 四、四个配置页签怎么用

- **基础配置**：控制角色、模型参数和历史轮数。
- **知识库绑定**：决定 Agent 可以检索哪些资料。
- **工具绑定**：允许模型调用内置、HTTP 或 MCP 工具；不代表每轮必调。
- **Workflow 绑定**：把已发布 Workflow 作为模型可选择的能力。

## 五、测试与发布

1. 点“测试对话”，先测试角色，再测试知识库，再测试工具。
2. 确认无误后点“发布”。
3. 点“复制链接”在无痕窗口验证。
4. 生产公开前进入“公开访问设置”配置密码、到期时间和允许 Origin。

测试问题：

```text
你能做什么？
试用期员工有几天年假？
请调用计算器计算 (18+27)*3。
```

## 六、常见问题

- **模型选择为空**：先在模型供应商创建启用的 Chat 模型。
- **知识库不生效**：文档须“已索引”，并在 Agent 中勾选、保存。
- **工具不调用**：检查绑定、工具状态、描述、必填参数和模型能力。
- **发布后 403**：Agent 被停用、公开设置过期或 Origin 不匹配。
- **Widget 聊天记录串号**：登录系统不要在 `index.html` 静态加载；用户信息就绪后动态传入唯一 `data-user-id`，退出时销毁 Widget，并确认浏览器没有缓存旧脚本。
- **回答太随机**：制度问答将 temperature 调到 0.1-0.3。

⚠️ API Key 只显示一次，只能保存在业务后端；轮换公开 Token 会让旧链接和所有旧 Widget 立即失效。

⚠️ `data-user-id` 只能避免正常使用中的串号，不是可信鉴权凭据。需要防恶意伪造时，由宿主后端验证用户后代理 Mia Service API，不能把 Agent API Key 放进浏览器。
