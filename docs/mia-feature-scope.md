# Mia 功能清单与范围取舍

Mia 是一个基于 Dify 思路简化出来的内部 AI Agent 平台。约束条件是：一个人开发，面向团队内部 20-50 人使用，本地部署。

本文用三个问题判断功能优先级：

1. 没有它，产品还成立吗？
2. 做到什么程度够用？
3. 能不能一句话说清楚？

## 产品定位

Mia 不应该一开始做成“小 Dify”。它更适合做成一个本地部署、轻量可控的内部 Agent + RAG 工作台。

一句话定义 Mia v0.1：

> Mia 是一个本地部署的内部 AI Agent 平台，让团队成员可以创建带知识库的 AI 助手，并通过统一聊天入口使用和排查它们。

## 核心必须有

这些功能如果缺失，Mia 作为内部 AI Agent 平台就很难成立，或者会明显失去核心价值。

| 功能             | 核心/边缘 | 没有它产品还成立吗               | 做到什么程度够用                                                          | 一句话说清楚                                  |
| ---------------- | --------- | -------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------- |
| Agent 创建与管理 | 核心      | 不成立                           | 能创建、编辑、删除 Agent，配置名称、说明、图标、系统 Prompt、模型和知识库 | 让团队能创建自己的 AI 助手。                  |
| Agent 对话界面   | 核心      | 不成立                           | 有 Agent 列表、对话窗口、历史会话、重新生成、复制回答                     | 让用户能直接和 Agent 聊天完成任务。           |
| 系统 Prompt 配置 | 核心      | 不成立                           | 支持一段系统指令，能保存最后修改时间；版本管理可以后置                    | 定义 Agent 的角色、边界和回答方式。           |
| 模型配置         | 核心      | 不成立                           | 先支持 OpenAI-compatible API，一个 Chat 模型，一个 Embedding 模型         | 让 Mia 能连接本地或私有模型服务。             |
| 知识库           | 核心      | 基本不成立                       | 支持创建知识库、上传文档、查看文档列表、删除文档                          | 让 Agent 能基于团队内部资料回答问题。         |
| 文档解析与切分   | 核心      | 基本不成立                       | 先支持 Markdown、TXT、PDF；自动抽文本、分块、入库                         | 把内部文档变成 Agent 可以检索的知识片段。     |
| 向量检索 / RAG   | 核心      | 基本不成立                       | topK 检索、相似度阈值、把检索片段注入 Prompt                              | 让 Agent 回答时先查资料，而不是只靠模型记忆。 |
| Agent 绑定知识库 | 核心      | 基本不成立                       | 一个 Agent 可绑定一个或多个知识库                                         | 控制不同 Agent 能访问哪些内部知识。           |
| 用户登录         | 核心      | 内部小范围勉强成立，但不建议缺失 | 账号密码登录即可，管理员手动创建用户                                      | 知道是谁在使用 Mia。                          |
| 基础权限         | 核心      | 勉强成立，但风险高               | 只做 Admin/User 两种角色                                                  | 区分谁能管理平台，谁只能使用 Agent。          |
| 对话日志         | 核心      | 勉强成立，但很难运营             | 记录用户、Agent、问题、回答、检索片段、模型、耗时、错误                   | 出问题时能回看 Agent 为什么这么答。           |
| 本地部署         | 核心      | 不成立                           | Docker Compose 一键启动 Web、API、数据库、向量库                          | 让 Mia 可以在团队自己的机器或服务器上跑起来。 |

## 重要但可简化

这些功能能显著提升 Mia 的可用性和可信度，但第一版不必做得很完整，可以先做窄。

| 功能              | 核心/边缘  | 没有它产品还成立吗       | 做到什么程度够用                                              | 一句话说清楚                             |
| ----------------- | ---------- | ------------------------ | ------------------------------------------------------------- | ---------------------------------------- |
| 工具调用          | 次核心     | 成立，但更像知识问答系统 | 第一版只做内置工具：HTTP 请求、当前时间、简单内部 API 调用    | 让 Agent 不只会回答，还能调用工具做事。  |
| 来源引用          | 次核心     | 成立，但可信度下降       | 回答下方展示引用文档名和片段，不做复杂高亮                    | 告诉用户答案来自哪些资料。               |
| 会话历史          | 次核心     | 成立，但体验差           | 用户能查看自己最近的会话，管理员可查全部日志                  | 让用户能回到之前的对话。                 |
| Agent 列表 / 目录 | 次核心     | 成立，但不好用           | 按名称、描述、创建者展示所有可用 Agent                        | 让团队成员找到自己需要的 Agent。         |
| 文档管理          | 次核心     | 成立，但维护困难         | 能查看文档状态、更新时间、分块数量、删除并重建索引            | 让管理员知道知识库里有什么。             |
| 简单用量统计      | 次核心     | 成立                     | 统计消息数、用户数、Agent 使用次数、模型调用次数              | 让团队知道 Mia 有没有被用起来。          |
| 错误与失败提示    | 次核心     | 成立，但不稳定感强       | 模型失败、检索失败、工具失败时给明确提示并写日志              | 让用户知道是哪里出错，而不是只看到空白。 |
| Prompt 模板       | 次核心     | 成立                     | 提供 3-5 个内置模板，如知识问答、代码助手、文档总结、客服助手 | 降低创建 Agent 的门槛。                  |
| 文件上传到对话    | 次核心偏后 | 成立                     | 支持单次上传 PDF/TXT/MD，让 Agent 总结或问答，不入长期知识库  | 让用户临时分析一个文件。                 |
| 简单反馈          | 次核心偏后 | 成立                     | 点赞/点踩，加可选文字反馈                                     | 收集哪些回答好，哪些回答需要改。         |
| 配置备份          | 次核心偏后 | 成立                     | 支持导出 Agent 和知识库配置，不必导出所有向量数据             | 防止本地部署误操作后很难恢复。           |

## 边缘可砍掉

这些功能对 Dify 这样的通用平台有价值，但对 Mia 的约束条件来说不是第一阶段重点。建议第一版直接砍掉，避免工程复杂度失控。

| 功能                 | 核心/边缘 | 没有它产品还成立吗 | 做到什么程度够用           | 一句话说清楚                               |
| -------------------- | --------- | ------------------ | -------------------------- | ------------------------------------------ |
| 可视化 Workflow 编排 | 边缘      | 成立               | 第一版不做                 | 用画布编排复杂 AI 流程。                   |
| 多应用类型           | 边缘      | 成立               | 第一版统一叫 Agent         | 不区分 Chatbot、Workflow、Text Generator。 |
| 插件市场             | 边缘      | 成立               | 不做                       | 从市场安装第三方插件。                     |
| 开放插件系统         | 边缘      | 成立               | 不做，最多保留内置工具接口 | 让开发者扩展 Mia 的工具和模型。            |
| MCP 发布             | 边缘      | 成立               | 不做                       | 把 Mia 的 Agent 发布给 MCP 客户端使用。    |
| 多租户 Workspace     | 边缘      | 成立               | 不做，单团队单空间         | 支持多个团队空间隔离使用。                 |
| 复杂 RBAC            | 边缘      | 成立               | 不做，先 Admin/User        | 精细控制每个人能看、能改、能发布什么。     |
| 应用市场 / 模板市场  | 边缘      | 成立               | 不做，最多 Agent 列表      | 像应用商店一样分发 Agent。                 |
| Web 嵌入组件         | 边缘      | 成立               | 不做                       | 把 Agent 嵌入到别的网站里。                |
| 对外 API 发布        | 边缘偏后  | 成立               | 第一版不做                 | 让外部系统通过 API 调用 Agent。            |
| 语音输入 / TTS       | 边缘      | 成立               | 不做                       | 用语音和 Agent 对话。                      |
| 图像生成             | 边缘      | 成立               | 不做                       | 让 Agent 生成图片。                        |
| 内容审核             | 边缘      | 成立               | 内部场景先不做             | 过滤敏感或违规输入输出。                   |
| Annotation Reply     | 边缘      | 成立               | 不做                       | 人工维护标准问答，命中后直接回复。         |
| A/B 测试             | 边缘      | 成立               | 不做                       | 比较不同 Prompt 或模型的效果。             |
| 复杂评测体系         | 边缘      | 成立               | 不做                       | 用测试集自动评估 Agent 表现。              |
| 计费 / 套餐          | 边缘      | 成立               | 不做                       | 按团队或用户收费。                         |

## Mia v0.1 最小闭环

如果只保留真正核心，Mia 第一版应该包含：

| 功能        | 一句话                                    |
| ----------- | ----------------------------------------- |
| 登录        | 让内部成员进入 Mia。                      |
| Agent 管理  | 创建和配置团队自己的 AI 助手。            |
| Prompt 配置 | 定义 Agent 怎么说、能做什么、不能做什么。 |
| 模型配置    | 连接本地或私有大模型服务。                |
| 知识库      | 上传团队资料，作为 Agent 的知识来源。     |
| RAG 检索    | 回答前先查内部资料。                      |
| Chat 界面   | 用户直接和 Agent 对话。                   |
| 日志        | 管理员能排查回答质量和系统问题。          |
| 本地部署    | 用 Docker Compose 在内网跑起来。          |

## 取舍原则

第一版只追求一个完整闭环：

> 管理员配置模型和知识库 -> 创建 Agent -> 团队成员使用 -> 通过日志持续调优。

凡是不服务于这个闭环的能力，都应默认后置或砍掉。

优先做这些：

- 能让用户创建 Agent 的功能。
- 能让 Agent 基于内部知识回答的功能。
- 能让管理员排查问题的功能。
- 能让系统本地稳定部署的功能。

暂时不做这些：

- 平台生态能力。
- 商业化能力。
- 多租户能力。
- 复杂工作流能力。
- 高级评测和实验能力。
- 多模态能力。

## 推荐开发顺序

1. 本地部署骨架：Web、API、数据库、向量库。
2. 用户登录与 Admin/User 权限。
3. 模型配置，先支持 OpenAI-compatible Chat 和 Embedding。
4. Agent 创建、编辑和列表。
5. Chat 对话主流程。
6. 知识库创建、文档上传、解析、切分和向量化。
7. Agent 绑定知识库，接入 RAG 回答。
8. 对话日志和错误日志。
9. 来源引用、会话历史和文档管理。
10. 简单工具调用、用量统计和反馈。
