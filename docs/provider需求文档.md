# 模型供应商需求与剩余工作

> 文档状态：按当前实现更新（2026-09-01）。统一 Chat/Embedding 调用网关、加密密钥、已配置状态、默认模型和模型同步等基础能力已经落地。

模型供应商模块目前已经形成“配置、测试、同步、默认选择、统一调用、流式遥测”的业务闭环。后续重点不再是补齐基础调用，而是完善能力声明、路由策略和生产韧性。

必须补

模型能力声明与路由：为模型声明 chat、stream、tool calling、vision、reasoning 等能力；Agent 运行时按输入和配置选择兼容模型。详细方案见 `model-capability-routing-technical-design.md`。

供应商差异映射：统一吸收各 Provider 对思考模式、工具调用、图片输入、Token 用量和错误格式的差异，避免业务层判断模型名称。

健康与韧性持久化：记录最近一次健康检查、耗时、错误、并发槽位、重试和熔断状态，并在管理页面可观察。

应该做
模型列表同步已具备基础能力；后续补供应商差异、失败提示和同步审计。
Provider 健康状态需要从单次测试扩展为持久化健康与熔断视图。
Provider 级超时 / 并发 / 重试配置：你之前规划过外部 LLM 慢且不稳定，这些配置目前还没落到 UI 和表结构里。
模型参数继续完善：除上下文长度、timeout、maxTokens 和思考能力外，补齐 stream、tool calling、vision 等结构化能力声明。
删除关联检查更完整：Provider 有模型时不能删；模型被 Agent 使用时也应该禁止删除或给出明确提示。

可以后置
供应商 Logo / 图标精细化：现在是文字 logo，占位可用，但不是真实品牌图标。
Marketplace 安装体验：目前是静态模板，不是真正市场；一期内部使用足够。
多 Key / 多凭据管理：现在一个 Provider 一组凭据，后续如果要按团队/用户/环境隔离 Key，再拆成独立凭据表。
成本与用量统计：需要 LLM 调用日志完成后再做。
模型自动降级 / fallback：要等真实调用网关、错误分类、熔断做好后再做。
一句话：统一模型调用网关已经完成，下一步最关键的是能力声明与可解释路由，其次是 Provider 级健康、并发、重试和熔断治理。
