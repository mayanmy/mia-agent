# 知识库模块需求文档

## 1. 背景

Mia 的核心目标是让团队可以创建带内部知识的 AI Agent。知识库模块负责把团队文档沉淀成可管理、可更新、可检索的知识资产，后续由 Retrieval 和 Chat 模块用于 RAG 回答。

知识库不是 Chat，也不是模型调用器。它关注的是知识资产生命周期：创建知识库、上传文档、解析文本、切分片段、查看状态、重建索引和删除维护。

## 2. 产品定义

一句话：

> 知识库是团队内部资料的管理容器，它把文档整理成 Agent 可以检索和引用的知识片段。

在 Mia 中，知识库承担三件事：

- 管理知识库本身。
- 管理知识库下的文档。
- 管理文档解析后的 chunks 和索引状态。

Embedding 生成和向量检索由 `retrieval` 模块负责，知识库模块只管理文档和 chunk 生命周期。

## 3. 用户角色

- Admin：创建知识库、上传文档、删除文档、重建索引、查看全部状态。
- User：v1 暂不开放知识库管理；后续可按权限允许查看或上传。
- Agent 创建者：后续在 Agent 配置中选择可绑定的知识库。

## 4. 核心价值

- 让 Agent 回答基于团队内部文档，而不是只依赖模型记忆。
- 让管理员知道知识库里有哪些资料、是否索引成功。
- 让文档更新、删除、重建索引可控。
- 为来源引用、日志排查和回答质量优化提供基础数据。

## 5. 模块边界

### 5.1 知识库负责什么

- 知识库 CRUD。
- 文档上传与文档元数据管理。
- 文档解析状态管理。
- 文档切分成 chunks。
- chunk 列表查看。
- 文档删除和软删除。
- 文档重建索引任务入口。
- 文档处理状态、错误原因展示。

### 5.2 知识库不负责什么

- 不直接调用 Chat Model。
- 不拼接 RAG Prompt。
- 不执行对话。
- 不做向量相似度检索。
- 不把检索结果注入聊天上下文。
- 不管理 Agent 绑定关系，绑定关系归 `agents` 模块。
- 不做复杂权限体系，v1 先由 Admin 管理。

## 6. 版本拆分

### 6.1 v1：知识库管理最小闭环

目标：管理员可以创建知识库、上传文档、看到文档处理状态，并让 Agent 后续可绑定这些知识库。

必须做：

- 知识库列表。
- 创建知识库。
- 编辑知识库名称和描述。
- 删除知识库，采用软删除。
- 文档上传。
- 文档列表。
- 文档状态展示。
- 支持 TXT、Markdown。
- 文档文本解析。
- 基础 chunk 切分。
- 记录 chunk 数量。
- 文档处理失败原因。
- 删除文档。
- 手动重建文档索引。
- Agent 绑定知识库的配置入口。

v1 中 retrieval 最小配合：

- 生成 embedding。
- 写入 `knowledge_embeddings`。
- Chat 通过 Agent 绑定的知识库做 topK 检索。
- 回答中返回基础来源引用。

暂不做：

- PDF / Word / Excel 解析。
- 网页抓取。
- 多文件夹层级。
- 文档版本管理。
- 权限到单知识库级别。
- 高级切分策略配置。
- 混合检索。
- rerank。
- 大规模索引队列。

### 6.2 v1.1：RAG 可用性增强

目标：让知识库可以稳定支撑实际问答，并能排查文档为什么没有被检索到。

必须做：

- 支持 PDF 解析。
- 支持 DOCX 解析。
- 上传文件大小限制。
- 文件 hash 去重。
- chunk 预览。
- 文档详情页。
- 索引进度展示。
- 索引失败重试。
- 检索测试入口。
- topK、相似度阈值基础配置。
- 来源引用展示优化。
- 文档删除后同步删除 chunks 和 embeddings。

可选：

- Markdown 标题层级感知切分。
- PDF 页码来源。
- 文档解析耗时记录。

### 6.3 v1.2：知识库运维能力

目标：让管理员可以持续维护知识库质量。

必须做：

- 批量上传。
- 批量删除文档。
- 批量重建索引。
- 知识库统计：文档数、chunk 数、索引成功率、最近更新时间。
- 文档状态筛选。
- 文档类型筛选。
- 文档搜索。
- 失败文档聚合。
- 后台任务列表。
- 重建整个知识库索引。

可选：

- 上传历史。
- 文档解析日志。
- chunk 导出。

### 6.4 v2：检索质量增强

目标：提高 RAG 命中率、准确性和可控性。

必须做：

- 多切分策略。
- 按知识库配置 chunk size / overlap。
- BM25 + 向量混合检索。
- rerank 接入。
- 查询改写。
- 引用片段高亮。
- 检索测试页展示 score。
- Agent 级检索参数覆盖。
- 低分检索结果过滤。

可选：

- FAQ 问答对导入。
- 标题路径注入。
- 文档元数据过滤。

### 6.5 v2.1：权限与协作

目标：让知识库从 Admin-only 变成团队可协作维护。

必须做：

- 知识库所有者。
- 知识库可见范围。
- User 上传权限。
- Agent 绑定知识库权限校验。
- 文档操作审计。
- 删除确认与恢复窗口。

可选：

- 知识库协作者。
- 只读 / 可编辑权限。

### 6.6 v3：高级知识资产管理

目标：面向更复杂资料体系和长期运营。

可做：

- 文档版本管理。
- 增量更新。
- 网页 / Sitemap 导入。
- 定时同步。
- 外部存储 MinIO / S3。
- 知识库导入导出。
- 多 embedding 模型 namespace。
- 多语言检索优化。
- 大规模数据分区和归档。
- 独立 Retrieval 服务。

## 7. 用户流程

### 7.1 创建知识库

1. 管理员进入知识库页面。
2. 点击创建知识库。
3. 填写名称、描述，选择 embedding 模型。
4. 保存后知识库出现在列表中。
5. 管理员进入知识库详情上传文档。

### 7.2 上传文档

1. 管理员进入知识库详情。
2. 点击上传文档。
3. 选择 TXT / Markdown 文件。
4. 系统创建文档记录，状态为 `pending`。
5. 后台任务解析文本并切分 chunk。
6. Retrieval 模块生成 embedding。
7. 文档状态变为 `indexed`。

### 7.3 文档失败处理

1. 管理员查看文档列表。
2. 失败文档显示 `failed` 和错误原因。
3. 管理员点击重试。
4. 系统重新解析、切分和向量化。

### 7.4 Agent 绑定知识库

1. 管理员进入 Agent 编辑页。
2. 在知识库 Tab 选择一个或多个知识库。
3. 保存 Agent。
4. Chat 时只检索该 Agent 绑定的知识库。

## 8. 状态设计

### 8.1 文档状态

```text
pending       已创建，等待处理
parsing       正在解析文本
chunking      正在切分
embedding     正在生成向量
indexed       已索引，可检索
failed        处理失败
deleted       已删除
```

### 8.2 知识库状态

```text
enabled       可用
disabled      停用
indexing      有文档正在处理
degraded      部分文档失败
```

## 9. 配置项

| 配置项                 | 阶段 | 必填 | 说明                  |
| ---------------------- | ---- | ---- | --------------------- |
| name                   | v1   | 是   | 知识库名称            |
| description            | v1   | 否   | 知识库说明            |
| embeddingModelConfigId | v1   | 是   | 使用的 Embedding 模型 |
| enabled                | v1   | 是   | 是否启用              |
| chunkSize              | v2   | 否   | 默认切分大小          |
| chunkOverlap           | v2   | 否   | chunk 重叠长度        |
| topK                   | v1.1 | 否   | 默认检索数量          |
| scoreThreshold         | v1.1 | 否   | 默认相似度阈值        |
| rerankModelConfigId    | v2   | 否   | rerank 模型配置       |
| visibility             | v2.1 | 否   | 可见范围              |

## 10. 业务规则

- 知识库名称不能为空。
- 知识库必须绑定可用的 Embedding 模型。
- Chat Model 不能作为 Embedding 模型使用。
- 删除知识库采用软删除。
- 删除知识库后 Agent 不应继续检索该知识库。
- 删除文档后，其 chunks 和 embeddings 不应继续被检索。
- 文档处理失败不能影响其他文档处理。
- 上传重复文件时优先提示已存在。
- v1 只允许 Admin 管理知识库。
- 文档原文、chunk 和 embedding 必须可以按知识库范围过滤。

## 11. 验收标准

### 11.1 v1 验收

- 可以创建、编辑、删除知识库。
- 可以上传 TXT / Markdown 文档。
- 可以查看文档列表和状态。
- 文档处理成功后可以看到 chunk 数量。
- 文档处理失败时可以看到错误原因。
- 可以删除文档。
- 可以重建文档索引。
- Agent 可以绑定知识库。
- Chat 会基于绑定知识库检索上下文。
- 回答中可以展示基础来源引用。

### 11.2 v1.1 验收

- 支持 PDF / DOCX。
- 支持文档详情和 chunk 预览。
- 支持检索测试。
- 文档删除后不再被检索到。
- 索引失败可以重试。

### 11.3 v2 验收

- 可以配置 chunk 参数。
- 支持混合检索和 rerank。
- 检索测试页展示 score 和命中来源。
- Agent 可以覆盖默认检索参数。
